# M1 유물 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 정예 유물 보상과 15종의 결정론적 전투 유물 효과를 저장 없는 런 재생에 추가한다.

**Architecture:** 유물 정의는 data에, 선언 모델과 sealed 효과는 domain에 둔다. 전투 엔진의 `_Sim`이 트리거를 한곳에서 해석하고 미리보기는 같은 해결 경로를 재사용한다. 런 엔진은 정예 보상 선택 id만 로그에 기록해 보유 목록과 후보를 재생한다.

**Tech Stack:** Flutter/Dart 3, flutter_test, 순수 domain 모델·엔진.

**Spec:** `docs/superpowers/specs/2026-08-27-m1-relics-design.md`

## Global Constraints

- `lib/domain/`은 Flutter, dart:ui, dart:io와 바깥 레이어를 import하지 않는다.
- 저장 골격은 `{seed, characterId, actionLog}`만 유지하며 보유 유물·후보를 저장하지 않는다.
- 난수 후보는 노드별 파생 시드와 `RngStream.reward`를 사용하며 기존 salt와 겹치지 않는다.
- 합법 런·전투 입력은 각각 `legalRunActions()`·`legalActions()`만 판단한다.
- UI, 보스 최상급 유물, 상점 유물 판매, 카드 강화는 범위 밖이다.
- 완료 전 `flutter analyze --fatal-infos`와 `flutter test`를 실행한다.
